    1. Egyptian Fraction Decomposition.

    An unit fraction is a fraction with numerator 1. The ancient Egyptians wrote every positive fraction as a sum of distinct unit fractions. For example,
    \begin{equation*} \frac{5}{7} = \frac{1}{2} + \frac{1}{5} + \frac{1}{70}. \end{equation*}
    🔗
    A standard greedy algorithm builds this decomposition one term at a time. If the current fraction is \(\frac{p}{q}\text{,}\) choose
    \begin{equation*} n = \left\lceil \frac{q}{p} \right\rceil, \end{equation*}
    so that \(\frac{1}{n}\) is the largest unit fraction that does not exceed \(\frac{p}{q}\text{.}\) Then subtract it and continue with the remainder.
    🔗
    Write a function egyptian(p, q) that takes positive integers p and q with \(0 < p < q\) and prints the Egyptian fraction decomposition of \(\frac{p}{q}\text{.}\) Use a while-loop that continues while p > 0. In each iteration:
    🔗
    1. Compute n = ceil(q / p).
      🔗
    2. Print the next term 1/n.
      🔗
    3. Update the fraction using
      \begin{equation*} \frac{p}{q} - \frac{1}{n} = \frac{pn - q}{qn}. \end{equation*}
      So set p = p*n - q and q = q*n.
      🔗
    Inputs:
    p
    🔗
    (1x1) double
    🔗
    positive integer numerator
    🔗
    q
    🔗
    (1x1) double
    🔗
    positive integer denominator, with \(p < q\)
    🔗
    Outputs:
    none
    🔗
    printed text
    🔗
    the Egyptian fraction decomposition of \(\frac{p}{q}\)
    🔗
    Test Cases ⤵︎
    🔗
    egyptian(5, 7)
egyptian(3, 11)
egyptian(7, 15)
    Expected ⤵︎
    🔗
    5/7 = 1/2 + 1/5 + 1/70
3/11 = 1/4 + 1/44
7/15 = 1/3 + 1/8 + 1/120
    Solution.
    function egyptian(p, q)
	origP = p;
	origQ = q;
	first = true;

	fprintf('%i/%i = ', origP, origQ)
	while p > 0
		n = ceil(q / p);
		if ~first
			fprintf(' + ')
		end
		fprintf('1/%i', n)

		p = p * n - q;
		q = q * n;
		g = gcd(p, q);
		if g > 0
			p = p / g;
			q = q / g;
		end

		first = false;
	end
	fprintf('\n')
end

    2. Archimedes’ Method for \(\pi\).

    Archimedes approximated \(\pi\) by using regular polygons inscribed in a unit circle. If a regular \(n\)-gon is inscribed in a circle of radius 1, then its perimeter is
    \begin{equation*} P_n = 2n\sin\left(\frac{\pi}{n}\right). \end{equation*}
    As \(n\) increases, the perimeter approaches the circle’s circumference \(2\pi\text{.}\) Therefore,
    \begin{equation*} \frac{P_n}{2} = n\sin\left(\frac{\pi}{n}\right) \end{equation*}
    approaches \(\pi\text{.}\)
    🔗
    Write a function archimedesPi(tol) that starts with n = 6 and repeatedly doubles n in a while-loop. In each iteration, compute
    \begin{equation*} \text{approx} = n\sin\left(\frac{\pi}{n}\right) \end{equation*}
    and continue until abs(approx - pi) <= tol. Display the step number, the current value of n, the approximation, and the error at each step. Return the final n, the final approximation, and the number of doublings used.
    🔗
    Because the error is proportional to \(1/n^2\text{,}\) doubling \(n\) reduces the error by about a factor of 4. So each doubling gives about \(\log_{10}(4) \approx 0.60\) additional correct decimal digits. This is much slower than Newton’s method, which typically doubles the number of correct digits each iteration once it is close to the root.
    🔗
    Inputs:
    tol
    🔗
    (1x1) double
    🔗
    stopping tolerance for abs(approx - pi)
    🔗
    Outputs:
    n
    🔗
    (1x1) double
    🔗
    final number of polygon sides
    🔗
    approx
    🔗
    (1x1) double
    🔗
    final approximation of \(\pi\)
    🔗
    steps
    🔗
    (1x1) double
    🔗
    number of times n was doubled
    🔗
    Test Cases ⤵︎
    🔗
    [n, approx, steps] = archimedesPi(1e-2)
[n, approx, steps] = archimedesPi(1e-6)
[n, approx, steps] = archimedesPi(1e-10)
    Expected ⤵︎
    🔗
    n = 24      approx = 3.132628613281238   steps = 2
n = 3072    approx = 3.141592105999271   steps = 9
n = 393216  approx = 3.141592653556370   steps = 16
    Solution.
    function [n, approx, steps] = archimedesPi(tol)
	n = 6;
	steps = 0;
	approx = n * sin(pi / n);
	err = abs(approx - pi);

	while err > tol
		fprintf('Step %2i: n = %8i, approx = %.15f, error = %.3e\n', ...
			steps, n, approx, err)
		n = 2 * n;
		steps = steps + 1;
		approx = n * sin(pi / n);
		err = abs(approx - pi);
	end

	fprintf('Step %2i: n = %8i, approx = %.15f, error = %.3e\n', ...
		steps, n, approx, err)
end

    3. Collatz Siblings.

    Write a function collatzSiblings(x, a, b) that uses collatzSteps to count how many other integers in the interval from a through b, inclusive, have the same Collatz step count as x.
    🔗
    For example, collatzSteps(6) = 8, but no other integer from 1 through 10 takes 8 steps, so collatzSiblings(6, 1, 10) should return 0.
    🔗
    Assume x, a, and b are positive integers with a <= x <= b.
    🔗
    Inputs:
    x
    🔗
    (1x1) double
    🔗
    reference integer whose Collatz steps are being matched
    🔗
    a
    🔗
    (1x1) double
    🔗
    starting integer in the interval
    🔗
    b
    🔗
    (1x1) double
    🔗
    ending integer in the interval
    🔗
    Outputs:
    count
    🔗
    (1x1) double
    🔗
    number of integers in \([a,b]\text{,}\) excluding x, with the same Collatz step count as x
    🔗
    Test Cases ⤵︎
    🔗
    count = collatzSiblings(6, 1, 10)
count = collatzSiblings(10, 1, 100)
count = collatzSiblings(27, 1, 1000)
count = collatzSiblings(6171, 1, 10000)
    Expected ⤵︎
    🔗
    count = 0
count = 1
count = 5

    Solution.
    function count = collatzSiblings(x, a, b)
	targetSteps = collatzSteps(x);
	count = 0;

	for n = a:b
		if n ~= x && collatzSteps(n) == targetSteps
			count = count + 1;
		end
	end
end

    🔗
    Use the Fibonacci sequence
    \begin{equation*} 0,\ 1,\ 1,\ 2,\ 3,\ 5,\ 8,\ 13,\ 21,\ \ldots \end{equation*}
    where each term is the sum of the previous two terms.
    🔗
    Inputs:
    none
    🔗
    —
    🔗
    start the sequence with \(0\) and \(1\)
    🔗
    Outputs:
    fib_result

    🔗

    Expected ⤵︎
    🔗

    function fib_result = fibonacciReport()
	prev2 = 0;
	prev1 = 1;

	fprintf('%i\n', prev2)
	fprintf('%i\n', prev1)

		current = prev1 + prev2;
		fprintf('%i\n', current)
		prev2 = prev1;
		prev1 = current;
	end

	fib_result = prev1;
end

    6. Decimal to Binary Conversion.

    To convert a positive integer from decimal to binary, repeatedly divide by 2 and record the remainders. Reading those remainders from bottom to top gives the binary representation.
    🔗
    For example,
    \begin{gather*} 13 \div 2 = 6 \text{ remainder } 1\\ 6 \div 2 = 3 \text{ remainder } 0\\ 3 \div 2 = 1 \text{ remainder } 1\\ 1 \div 2 = 0 \text{ remainder } 1 \end{gather*}
    so \(13_{10} = 1101_2\text{.}\)
    🔗
    Write a function called toBinary that takes a positive integer n and returns its binary representation as an ordinary base-10 integer whose digits are the binary digits. For example, toBinary(13) should return 1101.
    🔗
    Use a variable named place that starts at 1 and is multiplied by 10 each iteration. If remainder = mod(n,2), then update the result with result = result + remainder*place.
    🔗
    Inputs:
    n
    🔗
    (1x1) double
    🔗
    positive integer to convert
    🔗
    Outputs:
    result
    🔗
    (1x1) double
    🔗
    base-10 integer whose digits are the binary digits of n
    🔗
    Test Cases ⤵︎
    🔗
    % Test 1
toBinary(1)
% Test 2
toBinary(10)
% Test 3
toBinary(13)
% Test 4
toBinary(255)
    Expected ⤵︎
    🔗
    % Test 1
ans = 1
% Test 2
ans = 1010
% Test 3
ans = 1101
% Test 4
ans = 11111111
    Solution.
    function result = toBinary(n)
	result = 0;
	place = 1;

	while n > 0
		remainder = mod(n, 2);
		result = result + remainder * place;
		n = floor(n / 2);
		place = place * 10;
	end
end

    9. Digital Root with Helper Functions.

    The digital root of a positive integer is found by repeatedly summing its digits until only one digit remains. For example,
    \begin{gather*} 9 + 8 + 7 + 5 = 29\\ 2 + 9 = 11\\ 1 + 1 = 2 \end{gather*}
    so the digital root of \(9875\) is \(2\text{.}\)
    🔗
    Write a function called digitalRoot that returns the digital root of a positive integer n. Use lastDigit and removeLastDigit as helper functions, and use while-loops to process the digits.
    🔗
    Inputs:
    n
    🔗
    (1x1) double
    🔗
    positive integer
    🔗
    Outputs:
    root
    🔗
    (1x1) double
    🔗
    digital root of n
    🔗
    Test Cases ⤵︎
    🔗
    % Test 1
digitalRoot(38)
% Test 2
digitalRoot(99)
% Test 3
digitalRoot(123456)
% Test 4
digitalRoot(999999)
    Expected ⤵︎
    🔗
    % Test 1
ans = 2
% Test 2
ans = 9
% Test 3
ans = 3
% Test 4
ans = 9
    Solution.
    function root = digitalRoot(n)
	while n >= 10
		temp = n;
		sum_digits = 0;

		while temp > 0
			sum_digits = sum_digits + lastDigit(temp);
			temp = removeLastDigit(temp);
		end

		n = sum_digits;
	end

	root = n;
end

    10. Build a Number from Random Digits.

    Write a function called buildRandomNumber that constructs a number from n randomly generated digits. Use a while-loop and generate each digit with randi([0,9]).
    🔗
    Treat the first generated digit as the ones digit, the second as the tens digit, the third as the hundreds digit, and so on. For example, if n = 4 and the generated digits are \(7\text{,}\) \(3\text{,}\) \(0\text{,}\) and \(5\text{,}\) then the final number is
    \begin{equation*} x = 7\cdot 10^0 + 3\cdot 10^1 + 0\cdot 10^2 + 5\cdot 10^3 = 5037. \end{equation*}
    🔗
    Print each step as the number is built. Use x for the current value, x0 for the previous value, k for the place value index, and digit for the random digit generated at each step.
    🔗
    Because the digits are random, your exact result will vary from one run to the next. Also note that if the last digit generated is 0, the returned number may display with fewer than n digits.
    🔗
    Inputs:
    n
    🔗
    (1x1) double
    🔗
    number of random digits to generate
    🔗
    Outputs:
    x
    🔗
    (1x1) double
    🔗
    constructed number
    🔗
    Example Calls ⤵︎
    🔗
    % Example 1
x = buildRandomNumber(1)
% Example 2
x = buildRandomNumber(4)
    What to Expect ⤵︎
    🔗
    % Example 1
% x is an integer from 0 to 9.
% One line of output is printed.

% Example 2
% x is an integer from 0 to 9999.
% Four lines of intermediate output are printed,
% followed by the final number.
    Solution.
    function x = buildRandomNumber(n)
	x = 0;
	x0 = 0;
	k = 0;

	while k < n
		digit = randi([0, 9]);
		fprintf('k = %i, digit = %i: ', k, digit);
		x = x + digit * 10^k;
		fprintf('x = %i + %i*10^%i = %i\n', x0, digit, k, x);
		x0 = x;
		k = k + 1;
	end

	fprintf('Final number: %i\n', x)
end

    Inputs:
    n
    🔗
    (1x1) double
    🔗
    positive integer
    🔗
    Outputs:

    🔗

    🔗

	end

    12. Random Walk to a Boundary.
